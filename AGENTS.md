# Правила інтерфейсу

Ці правила діють для всього проєкту: всіх екранів, компонентів, мокапів і майбутніх змін.

- Інтерфейс має містити лише елементи, потрібні для поточної дії користувача.
- Не додавати слогани, декоративні підзаголовки, рекламні описи, переліки переваг, повторення очевидного та ілюстрації без функціональної потреби.
- Не показувати технічні деталі реалізації, внутрішню конфігурацію чи недоступні інтеграції як постійні підписи. Якщо функція не налаштована, приховати її недоступну дію.
- У користувацьких повідомленнях не показувати request ID, trace ID, внутрішні коди помилок, HTTP-статуси чи stack traces. Ці дані залишаються в API та засобах діагностики; UI містить зрозуміле пояснення й потрібну дію.
- Кожен підпис має називати поле/дію, пояснювати необхідне обмеження або повідомляти про фактичний стан, помилку чи результат.
- Пояснення показувати в потрібному контексті й стисло. Не прибирати потрібні validation errors, попередження про втрату даних і повідомлення про результат операції.
- Не додавати перемикачі, мовні мітки чи інші контролі без реальної функції.
- Мокапи — візуальний орієнтир; ці правила й актуальні вимоги користувача мають пріоритет над декоративними елементами мокапів.

Під час UI-змін перевіряти вигляд і адаптивність на desktop та мобільному екрані.

# Зовнішні налаштування

Потрібні зміни в Google Cloud повідомляти користувачу окремо від локальних змін коду. Не вносити їх автоматично: користувач налаштовує Cloud сам або окремо доручає конкретну зміну.

# Черга змін редактора після ручної перевірки

Станом на 19 листопада 2026 року реалізовано W01–W11 і браузерне прев’ю чернеток за R01.

Орієнтири: досвід IDE, перемикач режимів прев’ю на зразок Android Studio, вкладки, дерево та історія на зразок JetBrains. Усі елементи мають виконувати реальну дію; іконки отримують зрозумілі tooltip і доступні назви. Перевіряти desktop і mobile. Нові продуктові блоки поза переліченими тут не додаються.

## W01 — Останній успішний PDF при відкритті проєкту

- [x] Обговорити контракт, строк зберігання та початковий стан.
- [x] Реалізувати й перевірити.

Під час відкриття проєкту автоматично знаходити та показувати останній успішний PDF прийнятого документа. За наявності доступного PDF не вимагати нової компіляції лише для появи панелі. Якщо новіші зміни ще не скомпільовані або компіляція впала, залишати попередній успішний результат. PDF ШІ-пропозиції не підміняє прийнятий документ; старіша ревізія, скомпільована пізніше, не витісняє новішу.

Погоджено початкову поведінку: якщо доступного останнього PDF немає, автоматично запускати компіляцію поточної збереженої ревізії при відкритті проєкту. Це стосується як першої компіляції, так і відсутнього чи простроченого артефакту. Якщо задача для цієї ревізії вже queued/running, підключатися до неї без дублювання. Недоступність API не трактувати як підтверджену відсутність PDF. Початкове очікування показує стан завантаження; shimmer належить до W04. Помилка компіляції завершує спробу й показує діагностику, без нескінченних автоматичних повторів.

Реалізовано GET `/compilations/latest-pdf` та POST `/compilations/ensure`. Семиденний TTL PDF поки збережено: за відсутності доступного результату запускається або підхоплюється поточна збережена ревізія. Продовження строку зберігання останнього PDF не потрібне для цього сценарію й залишається окремим можливим рішенням. Обкладинка проєкту — окремий PNG зі своїм життєвим циклом.

Готово, коли reload і повторне відкриття показують доступний попередній PDF без зайвої компіляції; за підтвердженої відсутності PDF автоматично запускається або підхоплюється одна задача поточної збереженої ревізії. Помилка compile й недоступність API мають зрозумілі окремі стани.

## W02 — Зрозумілі режими робочого простору

- [x] Визначити режими, іконки й початкову розкладку.
- [x] Реалізувати й перевірити.

Перемикач іконками має режими «Лише код», «Код і PDF» та «Лише PDF». На широкому екрані початково відкриваються обидві панелі. На вузькому екрані початково відкривається код, доступні лише режим коду й режим PDF.

Рішення цього пункту задає структуру для PDF, нижньої діагностики та подальшого resize. Не додавати режими, які реально не працюють.

## W03 — PDF як документ із безперервною прокруткою

Іконки завантаження та відкриття PDF в іншій вкладці готові.

- [x] Визначити панель керування, масштабування й збереження позиції.
- [x] Реалізувати й перевірити.

- Усі сторінки розташовані послідовно згори вниз; прибрати кнопки «Попередня/Наступна».
- Масштаб змінюється кнопками, колесом із Ctrl/Cmd або жестом двома пальцями. «За шириною» повертає автоматичну підгонку. Звичайне колесо прокручує документ.
- Завантаження PDF — кнопка з іконкою. Окремо — іконка відкриття PDF у новій вкладці.
- При заміні PDF зберігати масштаб і позицію читання: сторінку та відносне місце на ній; якщо сторінок стало менше, вибирати найближчу доступну позицію.
- Новий результат підміняє старий після підготовки, без стрибка на початок і без проміжного порожнього екрана.
- Для великих PDF рендерити видимі й сусідні сторінки з обмеженням пам’яті, зберігши текстовий шар.

Кнопки завантаження й відкриття в іншій вкладці використовують PDF, показаний у переглядачі. Відкриття використовує Blob URL отриманого документа без токена в адресі.

## W04 — Очікування компіляції та діагностика

Готові спрощені статуси, відкладений shimmer і компактний індикатор оновлення зі збереженням видимого PDF.

- [x] Обговорити shimmer й поведінку нижньої панелі.
- [x] Реалізувати й перевірити.

Прибрати користувацькі статуси на кшталт «У черзі»: queued/running залишаються внутрішніми станами. Для початкового очікування показувати контур аркуша зі shimmer. Коли PDF уже є, залишати його читабельним; погодити ненав’язливий індикатор оновлення замість перекриття всього документа. Анімація враховує reduced motion.

Помилки й попередження компіляції показуються в нижній панелі. Нова помилка відкриває панель, а попередження доступні за лічильником. Клік по імені файла відкриває його в редакторі. Коли наступна збірка проходить без помилок, панель згортається, навіть якщо її відкрили вручну. Помилки збереження й конфлікти мають власні повідомлення.

Зараз backend повертає для діагностики файл, але не точну позицію. Точний перехід до рядка потребує серверної підтримки; поточний файл можна відкривати одразу.

## W05 — Постійна автокомпіляція після автозбереження

- [x] Обговорити затримки, чергу та обробку помилок.
- [x] Реалізувати й перевірити.

Автокомпіляція працює постійно після успішного збереження змінених вхідних файлів. Окрема зміна контексту або стану інтерфейсу не запускає збірку. Іконка «Скомпілювати» дає змогу вручну повторити збірку поточної збереженої ревізії.

Якщо під час збірки збереглися нові зміни, редактор запам’ятовує лише найновішу ревізію. Коли збірка закінчується й актуальні правки збережено, запускається наступна. Якщо активний статус невідомий, його можна перевірити перед наступною збіркою. Після синтаксичної помилки потрібна нова зміна або ручний повтор. Непідтверджене збереження й конфлікт не запускають збірку.

Залежить від W01–W04: старий PDF залишається видимим, новий оновлює його без втрати масштабу та прокрутки, а помилки з’являються знизу.

## W06 — Історія у широкому діалозі

- [x] Обговорити структуру діалогу та перегляд поточної версії.
- [x] Реалізувати й перевірити.

Історія відкривається поверх редактора у широкому діалозі, а на вузькому екрані займає весь екран. Адреса `/history` відкриває той самий діалог. Кнопка закриття або Escape повертають до відкритого файла і позиції в PDF. Усередині можна вибрати версію, переглянути файли та текст, порівняти зміни й підтвердити відновлення.

Поточна версія доступна для вибору й перегляду. Інші версії порівнюються з поточною. Підтверджене відновлення створює нову ревізію. За наявності незбережених змін дія відновлення заблокована.

## W07 — Вкладки файлів і контексту

- [x] Обговорити модель вкладок і місце відкриття контексту.
- [x] Реалізувати й перевірити.

Вкладки файлів прив’язані до ідентифікатора файла й зберігаються під час навігації в межах відкритого проєкту. Контекст має одну вкладку в тій самій смузі. Повторний виклик переходить до вже відкритої вкладки.

Порядок вкладок можна змінити перетягуванням або через Alt зі стрілкою. Меню доступне через правий клік або Shift+F10 і дозволяє закрити одну вкладку, інші, усі чи вкладки праворуч. Перемикання й повторне відкриття файла зберігають курсор, прокрутку, історію редагування й чернетку.

## W08 — Дерево файлів і контекстні дії

- [x] Реалізовано меню файлів, доступ із клавіатури й мобільну кнопку дій.

Перейменування, видалення, вибір головного файла й заміна ресурсу доступні в меню файла в дереві. На десктопі меню відкривається правим кліком, Shift+F10 або клавішею контекстного меню. На мобільному його відкриває кнопка біля файла. Меню може діяти на файл, який зараз закритий у редакторі. Зірочка праворуч позначає головний файл.

## W09 — Створення та завантаження в обрану папку

- [x] Готові створення й перейменування в дереві та вибір існуючої папки призначення.
- [x] Додано завантаження готових текстових і Typst-файлів.

Кнопка «Додати до проєкту» пропонує створення файла чи папки й завантаження. Для кнопки «Додати до проєкту» місце створення визначає вибір у дереві. На десктопі клік по порожній частині дерева або Esc скидають вибір і повертають місце створення до кореня. На десктопі ім’я вводиться безпосередньо в дереві, а на мобільному — у нижній панелі. Для переміщення й завантаження папку обирають зі списку. Меню «Файл», «Вигляд» і «Проєкт» об’єднують команди редактора, зокрема перейменування й видалення проєкту. На мобільному вони згруповані під кнопкою «Меню».

Завантаження приймає зображення, PDF, шрифти та файли `.typ`, `.txt`, `.md`, `.csv`, `.tsv`, `.json`, `.yaml`, `.yml`, `.toml` і `.bib`. Текст має бути у UTF-8 і може бути порожнім. Кілька окремих файлів можна додати в одну папку однією операцією. Ліміти на файл — 1 МіБ для тексту та 10 МіБ для ресурсів.

## W10 — Операції над папками та drag-and-drop

- [x] Реалізовано збереження порожніх папок та їхні операції в дереві.
- [x] Реалізовано перетягування в дереві та завантаження окремих файлів із файлового менеджера.

Порожні папки зберігаються у версіях проєкту й відображаються в історії. Дерево підтримує створення, перейменування, переміщення й видалення папок із підтвердженням.

На десктопі дерево підсвічує папку призначення або корінь. Перетягування всередині дерева відкриває діалог переміщення, а перетягування окремих файлів із комп’ютера відкриває діалог завантаження. Папку в дереві можна перемістити до іншої папки або до кореня. Цілі папки з комп’ютера не імпортуються. На мобільному доступні меню дій і вибір файлів.

Переміщення папки змінює шляхи всіх її файлів в одній ревізії та зберігає ID файлів і відкриті вкладки. Переміщення й перейменування разом зі зміною шляхів зберігають розпізнані літеральні посилання на файли проєкту у вихідних `.typ`-файлах. Підтримуються `include`, `import` і статичні аргументи стандартних функцій читання ресурсів. Обчислювані шляхи та виклики з неоднозначним значенням потребують ручного оновлення.

## W11 — Resize панелей і локальне збереження розкладки

- [x] Визначено роздільники, межі розмірів і склад збереженого стану.
- [x] Реалізовано й перевірено.

Ширина дерева файлів, співвідношення коду й PDF та висота відкритої діагностики змінюються перетягуванням або клавішами зі стрілками. Home і End встановлюють крайні розміри, подвійне натискання на роздільнику відновлює початковий розмір. Роздільники ширини доступні між видимими панелями. На мобільному висота відкритої діагностики змінюється дотиком.

Розміри панелей зберігаються локально для акаунта. Режим, видимість десктопної панелі файлів, відкриті вкладки та їхній порядок, активна вкладка, масштаб і місце читання PDF зберігаються для конкретного проєкту в межах акаунта. У сховище записуються лише параметри інтерфейсу та ідентифікатори вкладок. На вузькому екрані режим двох панелей тимчасово показує лише код. Якщо сховище недоступне, редактор працює з налаштуваннями поточного сеансу.

«Вигляд → Скинути розкладку» повертає розміри, режим та видимість панелі файлів до початкових налаштувань. Відкриті вкладки й місце читання PDF зберігаються.

## R01 — Дослідження швидкої компіляції та SmartTeX

- [x] Дослідити механізм за доступними знімками коду SmartTeX.
- [x] Виміряти поточний цикл і запропонувати варіанти.
- [x] Реалізувати локальне прев’ю чернетки з доступом до PDF збереженої ревізії.

Це самостійне дослідження після базового W05; воно не блокує історію, вкладки та дерево. Порівняти звичайну компіляцію після автозбереження з інкрементальним або довготривалим ізольованим compiler session. Виміряти час від правки до PDF, окремо debounce/save, dispatch/polling, запуск sandbox, сам Typst, завантаження та рендер. Врахувати, що фонова PNG-обкладинка зараз також використовує compile worker: вона не повинна затримувати часті оновлення PDF або створювати зайву роботу.

Знайдено часткові знімки SmartTeX із гілками одноразового запуску Typst із Docker і без нього. Активна конфігурація та швидкість SmartTeX лишаються непідтвердженими. У Typstoria виміряно затримку від правки до видимого PDF на локальному стенді та окремо порівняно одноразовий запуск Typst із `watch`. [Заміри й варіанти](17-workspace-compilation-latency.md)

Чернетка компілюється в браузері. Compile API продовжує формувати PDF для збережених ревізій. [Прев’ю під час редагування](15-workspace-output-history.md#превю-під-час-редагування)

## Як рухаємося

Основна черга: W01 → W02 → W03 → W04 → W05 → W06 → W07 → W08 → W09 → W10 → W11. R01 обговорюється окремо після появи базової автокомпіляції.

Для кожного пункту: спочатку погодити поведінку й вигляд; після доручення реалізувати frontend/backend разом, якщо потрібно; перевірити desktop/mobile, втрату даних, авторизацію та регресії відповідно до змін; оновити цей список і документацію. Комітити завершений блок після перевірок; дрібні рішення під час обговорення не комітити окремо.

# Межі фронтенду

Статус: проєкт v0.1, 26.10.2026. Погоджено користувачем: TypeScript + Vue, проєктування та каркас застосунку. Основні мокапи й дизайн-система опрацьовуються окремо за коротким брифом.

## 1. Призначення

Typstoria — вебсередовище для технічної документації на Typst. Користувач працює з приватним багатофайловим проєктом, контекстом, PDF і версіями. Зовнішній ШІ працює через MCP та створює пропозиції; рішення щодо їх застосування користувач приймає у вебінтерфейсі.

Вебклієнт відповідає за взаємодію та збереження локальних незавершених правок. Право доступу, поточну ревізію, прийняття пропозицій і компіляцію визначає сервер.

## 2. Основні можливості повної поставки

Номери F/N — з [бекенд-вимог](https://github.com/Typstoria/backend/blob/main/docs/backend/01-scope.md), без дублювання другого реєстру.

| Група             | Що має бути у вебі                                                             | Вимоги бекенду     |
| ----------------- | ------------------------------------------------------------------------------ | ------------------ |
| Обліковий запис   | Register/login/logout, verify/reset, Google login та явне linking              | F01                |
| Проєкти           | Приватний список, створення, назва, видалення, дерево та entrypoint            | F02, F04, F08      |
| Редактор і PDF    | Редагування, save, compile, diagnostics, outline, completion/format/navigation | F05, F11, F16      |
| Review та історія | Повний diff proposal, validate/accept/reject/stale; порівняння і restore       | F09, F10           |
| Контекст          | Текст, матеріали та витяги, пошук, анотації                                    | F03, F12, F13      |
| Шаблони та архіви | Системні/власні шаблони, share/copy/revoke, ZIP import/export                  | F04, F14, F15, F17 |
| Інтеграції        | Інструкції MCP, PAT, OAuth consent/revoke, GitHub backup                       | F06, F07, F18, F19 |

Скорочений набір мокапів не скорочує погоджений функціональний обсяг бекенду. Реалізація йде інкрементами; поточна задача не включає завершення всіх цих функцій.

## 3. Незмінні правила

- Збереження тексту й успішна компіляція — окремі результати. Помилковий Typst можна зберегти.
- `409` не знищує локальний текст і не запускає save з новою базою автоматично.
- PDF має видимий зв’язок із входами компіляції. Незбережений текст, stale PDF і compile failure відрізняються.
- ШІ не змінює основний проєкт без web acceptance. Контекст, матеріали й анотації також проходять review.
- Прийняття Typst error потребує окремої дії користувача; infrastructure failure не прирівнюється до Typst error.
- Токени не додаються в URL; auth cookies та refresh відсутні. Приватність забезпечує backend, route guard лише покращує UX.

## 4. Поза обсягом

Вбудований ШІ-чат, оплата LLM, LaTeX, live collaboration, ролі організацій, двосторонній Git sync, OCR та автоматичне визначення семантичної застарілості документа. Offline-first не заявлено: локальний draft допомагає відновитися, але не створює офлайн-версію серверного проєкту.

Інтерфейс і документація початково українською. Мультимовність і темна тема не блокують каркас; потребу уточнити до відповідного дизайн-етапу.

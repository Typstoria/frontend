# Компіляція, PDF та історія версій

При відкритті редактора PDF-панель на desktop з’являється автоматично. Спершу `GET /compilations/latest-pdf` знаходить останній доступний успішний PDF прийнятого документа та його номер ревізії. Якщо новіші правки ще не скомпільовані або компіляція впала, показується попередній доступний результат. На вузьких екранах відкривається код, а PDF доступний через іконку «Лише PDF».

Лише підтверджена відсутність результату запускає `POST /compilations/ensure`. Сервер повторно перевіряє PDF, підхоплює активну задачу поточної збереженої ревізії або створює її. Паралельне відкриття вкладок повторно використовує цей запуск. Недоступність API, некоректна відповідь або помилка читання PDF мають окремий стан із повтором. Під час пошуку й компіляції можна редагувати файл. Вихід зупиняє запити й опитування статусу.

TTL PDF лишається семиденним. Якщо при відкритті немає доступного артефакту, зокрема після expiry, автоматично запускається поточна збережена версія. Чернетка з пам’яті вкладки сама по собі не передається компілятору.

Редактор компілює після підтвердженого збереження змін до файлів або головного файла. Зміна лише контексту не запускає збірку. Запит прив’язаний до конкретної збереженої ревізії. Якщо під час збірки збереглися нові правки, після завершення компілюється лише найновіша ревізія. Збірку з невідомим статусом можна перевірити перед наступним запуском. Іконка **Скомпілювати** повторює збірку поточної збереженої ревізії.

Іконки **Лише код**, **Код і PDF** та **Лише PDF** задають розкладку. Спільний режим доступний на широких екранах. PDF прокручується сторінка за сторінкою згори вниз. Масштаб можна змінити кнопками, колесом із Ctrl/Cmd або жестом двома пальцями. «За шириною» підганяє документ під доступну панель. Панель зберігає масштаб і місце читання при перемиканні режиму та після заміни PDF. Якщо сторінок стало менше, позиція обмежується останньою доступною сторінкою. Іконки в панелі завантажують PDF або відкривають його в новій вкладці. Під час збірки й після помилки доступний попередній успішний PDF. Під час першої підготовки PDF індикатор у вигляді аркуша з’являється після 200 мс.

Діагностика розташована в нижній панелі. Помилка відкриває її автоматично, а попередження доступні за кнопкою з лічильником. Після збірки без помилок панель згортається, навіть якщо її відкрили вручну. Ім’я файла веде до вихідного тексту, якщо діагностика належить поточній ревізії. Backend повертає файл без точного діапазону в тексті.

PDF запитується з Bearer-токеном і завантажується у PDF.js у локальному worker. Після завершення терміну доступності панель прибирає артефакт. Статус задачі оновлюється через GET з інтервалом від 600 мс до 5 с та двохвилинним вікном спостереження. Після паузи можна повторно перевірити той самий job. Спостереження зупиняється після завершення задачі або виходу з проєкту. Серверний SSE endpoint ще відсутній.

**Історія версій** відкривається в діалозі поверх редактора за адресою `/projects/:projectId/history`. На вузькому екрані діалог займає весь екран. Кнопка закриття та Escape повертають фокус і залишають вкладки та PDF у тому самому стані. Порівняння показує зміни від вибраної версії до поточної. Можна відкрити текстові файли вибраної версії для читання. Історія також показує контекст, зміну головного файла та метадані ресурсів. Сервер обмежує обсяг текстових порівнянь.

Відновлення потребує підтвердження. Воно створює нову версію з файлами, головним файлом і контекстом вибраної версії. Поточна версія зберігається в історії. Якщо в іншій вкладці з’явилася нова версія, потрібно переглянути оновлене порівняння і підтвердити дію знову. Після втрати відповіді повтор у тій самій сесії використовує той самий idempotency key. Після завершення сесії результат перевіряється в історії.

Backend worker за замовчуванням компілює в окремому Docker-контейнері з digest-pinned Typst image; API та frontend не залежать від способу ізоляції. Для Linux лишився явний адаптер Bubblewrap/systemd. Інструкції запуску й обмеження описано в `docs/backend/15-compilation.md` бекенду.

## Перевірка зі справжнім backend

14 листопада 2026 року пройдено browser smoke у Chromium на desktop 1440×900 та mobile 390×844 зі справжніми API, PostgreSQL, compile worker, Docker Typst і Git history worker, без підміни API. Для перевірки створено окрему тимчасову БД і два тестові акаунти з підготовленими підтвердженими адресами; доставку пошти цей сценарій не перевіряв.

На обох екранах перевірено вхід, створення проєкту, автозбереження українського тексту та reload, компіляцію двосторінкового PDF, текстовий шар, пагінацію й завантаження. Реальна помилка Typst зберігає текст і відкриває файл через діагностику. History/diff показують фактичні зміни; restore створює нову ревізію, оновлює редактор і зберігає попередні версії; Git mappings переходять у ready. PDF недоступний без авторизації, інший акаунт не може прочитати проєкт. Переповнення сторінки та необроблених помилок браузера не виявлено.

Після smoke тимчасову БД, blobs, Git repositories і scratch видалено. Окремо пройдено 61 інтеграційну backend-перевірку компіляції, історії, пропозицій і MCP в ізольованій тестовій БД; real-compiler сценарії використовували Docker Typst. Firefox/WebKit, реальна доставка пошти та production provisioning залишаються окремими перевірками.

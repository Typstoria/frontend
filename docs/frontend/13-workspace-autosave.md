# Текстовий редактор та автозбереження

Статус: перша частина FE2b. Проєкт зі списку відкриває захищений `/projects/:projectId`. Доступні наявні текстові файли; створення/перейменування/видалення файлів, upload, контекст, LSP, компіляція та PDF залишаються наступними блоками.

## Читання та редактор

`GET /state` визначає базовий snapshot за `revision.id`. Текст завантажується при виборі файла через `GET /files/:fileId?revisionId=…`; file/revision IDs перевіряються у відповідях. Завершення збереження під час читання файла спричиняє повторне читання з новою ревізією. Пізні відповіді попереднього вибору чи демонтованої сторінки не змінюють редактор. Binary-файл показує фактичний стан без спроби редагувати його як текст.

Робочий простір використовує компактне компонування IDE: шапка, панель проєкту й активний файл; редактор займає решту вікна з однією внутрішньою прокруткою. На desktop дерево файлів має згортані каталоги, на mobile воно відкривається модальною бічною панеллю та повертає фокус після закриття. Стан каталогів зберігається при відкритті панелі та зміні ширини. Назва, дата й вільна область рядка проєкту утворюють одне посилання; меню дій відокремлене.

CodeMirror 6 завантажується лише у workspace; окремі `EditorState` зберігають undo і selection за сталим fileId, а `scrollSnapshot` відновлює позицію прокрутки. Є номери рядків, перенесення довгих рядків, двопробільний Tab, український текст та emoji. Escape, потім Tab дозволяють вийти клавіатурним фокусом. Після явного узгодження конфлікту попередній editor history очищується.

Spike API підтвердив immutable EditorState, history, UTF-16 та composition events; browser checks перевіряють основну поведінку адаптера. Typst grammar поки не підключено: знайдені сторонні кандидати не пройшли достатньої перевірки для цього інкременту. Немає підсвічування Typst, completion, форматування чи LSP. Реальний системний IME та навантажувальні fixtures потребують окремої перевірки перед мовними функціями.

## Автозбереження

За актуальною вимогою користувача ручне збереження замінено автозбереженням після 1000 мс без змін. Під час IME composition таймер призупинено. `Ctrl/Cmd+S` негайно запускає той самий механізм, без окремої кнопки збереження. Серверна ревізія створюється лише для зміненого snapshot; відсутність правок не створює запит.

Один atomic `POST /changes` містить усі dirty текстові файли, `baseRevisionId` і новий Idempotency-Key. Поки запит виконується, можна продовжувати редагувати й перемикати файли; другий запит не запускається. Success оновлює базові тексти саме до відправлених значень, залишаючи наступні правки dirty; наступний debounce використовує нову базову ревізію.

Backend limits перевіряються до відправлення: до 200 операцій, 1 МіБ UTF-8 на текст файла та 8 МіБ JSON на пакет. Перевищення залишає текст у редакторі й дозволяє завантажити копію. Сервер остаточно перевіряє всі обмеження.

Мережевий обрив, timeout, некоректна success-відповідь або серверна помилка залишають результат невідомим. Нові автозапити зупиняються: користувач натискає «Повторити збереження», що відправляє незмінний пакет із тим самим ключем. Лише після його успіху відправляються новіші правки. Немає нескінченних фонових retry. Відоме відхилення запиту залишає draft і показує потрібну дію.

## Конфлікт та захист чернетки

Після `409` автоматичного перезапису немає. «Порівняти версії» завантажує окремий поточний snapshot і тексти змінених файлів. Для кожного файла поруч показані серверний текст і редагований результат; база та початкові локальні зміни доступні в розгортаному блоці; можна явно вибрати серверний текст. Видалений або замінений binary-файлом текст не відтворюється автоматично: є попередження та завантаження копії. «Продовжити автозбереження» підтверджує нову базу й відновлює автозбереження. Новий конкурентний запис знову спричинить конфлікт. Повторне порівняння не стирає вже введений merge.

Route navigation і явний logout потребують підтвердження втрати локальних правок або непідтвердженого запису. Logout не відкликає сеанс до цього рішення. `beforeunload` встановлюється лише поки є такі дані; браузер показує власне стандартне попередження.

При завершенні сеансу чернетка, незавершений пакет та ручне об’єднання утримуються в пам’яті цієї вкладки для повторного входу того самого користувача. Новий акаунт очищує recovery і не бачить попередні тексти. Повернення після входу дозволяє лише валідний внутрішній project route. Запити/таймери скасовуються при unmount.

Recovery не переживає закриття чи reload вкладки; IndexedDB recovery ще не реалізовано. Завантажена JSON-копія містить завантажені тексти та, за наявності, незавершене ручне порівняння; це резервна чернетка, а не повний ZIP проєкту й не формат автоматичного імпорту. Проєктні тексти не записуються у localStorage/sessionStorage.

## Перевірки

Unit tests покривають debounce/composition, atomic batches, введення й undo під час save, незмінний retry, ручний конфлікт/deletion, recovery та відсікання пізніх відповідей, UTF-8 limits і response validation. Playwright перевіряє desktop/mobile Chromium, основні editor journeys, повторний вхід, ізоляцію акаунтів і dirty guards із підмінами API.

Окремий browser smoke зі справжнім API та PostgreSQL перевірив автозбереження, читання збереженої ревізії, reload і конфлікт двох вкладок із ручним об’єднанням на desktop 1440×900 та mobile 390×844. Тимчасові записи та приватні файли прибрано. Перевірки frontend не доводять готовність PDF, LSP чи системного IME на всіх платформах.

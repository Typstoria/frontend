# Короткий бриф: дизайн-система та основні мокапи

Статус: основні мокапи M01–M04 надано. M04 використано для auth-інтерфейсу; M01–M03 залишаються орієнтирами наступних етапів. Нижче — стислий бриф базової системи та чотирьох екранів.

## 1. Напрям

**Обов’язкове правило для всього проєкту:** інтерфейс містить лише те, що допомагає виконати поточну дію. Без слоганів, декоративних підзаголовків, рекламних описів, переліків переваг, нефункціональних контролів і постійних технічних пояснень. Залишаються назви полів/дій, необхідні обмеження та фактичні стани, помилки й результати. Недоступні інтеграції приховуються. Це правило застосовується до всіх екранів і має пріоритет над декоративним вмістом мокапів; інструкція для розробки — у [AGENTS.md](../../AGENTS.md).

Спокійний робочий інструмент для технічної документації: чітка ієрархія, компактні controls, багато місця тексту й PDF. Менше декоративних блоків, більше зрозумілих станів документа. Початково світла тема; українські тексти. Вебінтерфейс містить редактор і review, вбудованого ШІ-чату немає.

З мокапів перенесено світлі поверхні, темно-синій текст, cyan accent, форму в окремій картці й знак листка. Auth містить заголовок, поля та потрібні дії; декоративну панель прибрано на всіх ширинах. Семантика відповідає API: без remember-me та спільних просторів, password policy — 6–128 символів без додаткових вимог.

## 2. Мінімальна дизайн-система

| Частина     | Що визначити                                                                                 |
| ----------- | -------------------------------------------------------------------------------------------- |
| Колір       | Background/surface/text/muted/border, один accent, success/warning/error; diff add/remove    |
| Типографіка | UI font із кирилицею, mono для Typst; 4–5 розмірів, читабельний line-height                  |
| Геометрія   | Крок відступів 4/8 px, control height ~40 px, радіуси й borders, ширини панелей              |
| Компоненти  | Button primary/secondary/danger, input/error, tabs, dialog, status badge, toast, empty state |
| Спеціальні  | File row, editor tab, diagnostic row, PDF toolbar, diff row, proposal decision panel         |

Для базових controls показати normal/hover/focus/disabled/error там, де застосовно. Status передається текстом/іконкою поряд із кольором. Keyboard focus видимий; modal має focus trap/return і зрозумілі назви дій. Орієнтир — WCAG AA (4.5:1 для звичайного тексту), перевірити готові комбінації інструментом; контраст тимчасових tokens не вважати вже сертифікованим.

## 3. Чотири мокапи

| №   | Екран                | Що обов’язково показати                                                                                                             |
| --- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| M01 | Проєкти              | Назва, кнопка створення, пошук, 3–4 реалістичні проєкти з датою/станом; маленький варіант empty                                     |
| M02 | Редактор + PDF       | Дерево файлів, активний main.typ, український Typst, PDF поруч, save/compile, окремі unsaved і stale PDF labels                     |
| M03 | Review ШІ-пропозиції | Мета, base/candidate version, список змін, diff, candidate PDF/diagnostics, accept/reject; компактний приклад compile-error warning |
| M04 | Вхід                 | Email/password, офіційна Google button placeholder, register/reset links, validation error; без вигаданого «запам’ятати мене»       |

Основний desktop frame: **1440×1000 px**. Достатньо одного додаткового mobile frame **390×844 px** для M02: source/PDF перемикаються, дерево згортається. Не потрібно зараз малювати окремо всі settings, imports, histories і OAuth screens.

Спільний приклад даних: проєкт «Архітектура системи», `main.typ`, `chapters/architecture.typ`, `assets/diagram.svg`; поточна ревізія 12, proposal version 3 від зовнішнього MCP-клієнта. Приклади — для мокапів, не API fixtures. PDF має відповідати видимому тексту, зміни — заявленій пропозиції.

## 4. Які картинки/матеріали потрібні

**Обов’язкові — самі макети екранів, а не декоративні ілюстрації.**

- 4 PNG-прев’ю M01–M04 та редагований оригінал у вибраному design tool. Для M02 ще один mobile PNG.
- Один реалістичний зразок сторінки українського технічного документа для PDF pane; краще реальний PDF, з якого отримано preview, ніж растрова картинка з нерозбірливим текстом.
- Один узгоджений набір простих SVG-іконок: файл/папка, compile, save, download, history, comment, link, check, warning. Одна товщина лінії; іконки не генерувати окремими різностильовими зображеннями.
- Логотип: на старті достатньо напису Typstoria. Окремий SVG-знак — лише якщо буде обраний у дизайн-проході.

Hero photos, фони, 3D-ілюстрації та окрема графіка для кожного empty state не потрібні. Шрифти й сторонні icons мають мати зрозумілу ліцензію. Google button дотримується офіційного GIS оформлення.

## 5. Бриф для дизайнера або інструмента мокапів

> Створи основні макети вебзастосунку Typstoria для технічної документації на Typst. Український UI, світла робоча тема, нейтральні поверхні й один спокійний accent. Чотири екрани: проєкти, трипанельний редактор із PDF, review зовнішньої ШІ-пропозиції з diff та рішенням, вхід. ШІ працює через зовнішній MCP-клієнт; чату всередині немає. Save і compile мають різні статуси, stale PDF позначений, пропозиція не застосована до acceptance. Використай читабельні реалістичні тексти, узгоджені компоненти та keyboard focus. Основні frames 1440×1000, один mobile editor 390×844. Підготуй також невелику сторінку tokens і базових controls.

Результат придатний до реалізації, коли підписані панелі й дії, зрозуміла різниця source/candidate/PDF, видимі основні error states, а components і tokens можна перенести в Vue/CSS. Не переносити весь екран як одну растрову картинку.

# Керування проєктами

Статус: FE2a. Захищений `/projects` використовує реальний Projects API. Текстові файли й редактор із автозбереженням реалізовано першим інкрементом FE2b; PDF та історія підключаються окремими блоками; бекенд уже має відповідні контракти.

## Поведінка

- У шапці — клікабельна іконка облікового запису та іконка виходу, з доступними назвами й підказками; email показується на сторінці профілю.
- Компактний список: назва, дата оновлення, меню перейменування/видалення. Порядок — ID за спаданням, а не дата оновлення.
- Сторінка завантажує по 20 записів; «Завантажити ще» передає exclusive cursor. Помилка наступної сторінки залишає вже завантажені рядки й той самий cursor для повтору. Повторний перехід на сторінку перечитує першу сторінку; окремої кнопки оновлення немає.
- Створення й перейменування використовують діалог з одним полем. Назва trim, 1–200 Unicode code points, без керівних символів. Остаточна перевірка — у бекенді.
- Видалення потребує окремого підтвердження з назвою та наслідком. Початковий фокус — на скасуванні. Сервер робить soft delete; UI не пропонує відновлення.
- Успішна зміна відображається після відповіді сервера. Назва залишається після помилки. Request IDs, статуси та внутрішні повідомлення не рендеряться.
- Порожній список показується тільки після успішного читання; API failure не підміняється порожнім станом або mock даними.
- Назва проєкту відкриває робочий простір `/projects/:projectId`; поведінка — у [13](13-workspace-autosave.md). Preview routes доступні напряму, посилань на них у навігації проєктів немає.

## Контракти

Усі маршрути мають prefix `/api` та Bearer підтвердженого власника. Сторонні/відсутні/видалені проєкти повертають 404.

| Запит                             | Використання                                                                |
| --------------------------------- | --------------------------------------------------------------------------- |
| GET `/projects?limit=20&cursor=…` | `{items, nextCursor}`, cursor опускається на першій сторінці                |
| POST `/projects`                  | `{title}` та `Idempotency-Key`; результат містить project/revision/file IDs |
| GET `/projects/:id`               | Канонічна назва, timestamps та currentRevisionId після створення            |
| PATCH `/projects/:id`             | `{title}`, повертає metadata; last-write-wins, без metadata version         |
| DELETE `/projects/:id`            | 204; повторний 404 UI вважає досягнутим видаленням                          |

Створення також створює порожній `main.typ` і ревізію №1. Git status не блокує список. `projects-api.ts` використовує generated DTO й перевіряє runtime metadata, IDs, дати та поступ cursor перед показом даних. Query кодується transport окремо від path.

Джерело: [приватні проєкти бекенду](https://github.com/Typstoria/backend/blob/main/docs/backend/12-project-creation.md) та актуальний OpenAPI.

## Повтори та життєвий цикл

Для однієї спроби створення генерується ключ. При мережевій помилці, втраті POST-відповіді або невдалому наступному GET повтор із тією самою назвою використовує цей ключ. Закриття й повторне відкриття діалогу на цій сторінці також зберігає назву/ключ. Зміна назви — новий намір з новим ключем. Автоматичних mutation retries немає.

Ключ живе лише до успіху або виходу зі сторінки. Після reload/повторного входу перед створенням варто перевірити список: ключ попередньої сторінки не зберігається. Дані проєктів і назви не пишуться в localStorage/sessionStorage. Auth token окремо зберігає identity service у localStorage за вимогою користувача.

Приватні запити проходять через auth session: 401 завершує сеанс, пізня відповідь попереднього сеансу відкидається. Unmount скасовує незавершені fetch і прибирає локальні дані/listeners. Перейменування з 404 прибирає недоступний рядок і пояснює результат у діалозі.

Завантаження списку й mutation не перетинаються. Поки mutation виконується, повторний submit і закриття діалогу блокуються; timeout transport — 15 секунд. Native dialog забезпечує inert background, focus containment та Escape; після закриття фокус повертається до кнопки дії, після видалення — до «Новий проєкт».

## Перевірки

`npm run check`: форматування, lint, типи, response-boundary/transport/session тести та production build. `npm run test:e2e`: CRUD, validation, pagination failure/retry, повтор створення після втрати відповіді, 404/401, pending submit, keyboard/focus, довгі назви та межі екранів 320–1440 px у desktop/mobile Chromium. API/GIS у цих тестах підмінені.

Окрема наскрізна перевірка використовує браузер, dev proxy, справжній API та PostgreSQL з тимчасовим підтвердженим користувачем: створення, перечитування списку, перейменування й видалення. Листи та Google для цього сценарію не потрібні. Тимчасові записи прибираються після перевірки.
